## Состояние

- Репозиторий: https://github.com/Ayuemin/Agent-Ayuemin; [debug APK](https://github.com/Ayuemin/Agent-Ayuemin/releases); [CI](https://github.com/Ayuemin/Agent-Ayuemin/actions/workflows/debug-apk.yml).

- Пользователь обнаружил: после нормального ответа приложение сохраняло `null` при запросе текста ~1000 символов. Изменён `ApiClient.kt` (коммит `30819fbc`): пустой `message.content` теперь должен быть ошибкой с `finish_reason`, но **реальный проблемный API повторно не проверен**. Важна проверка reasoning-форматов, `max_tokens=1024` и наличия текста в ответе.
- GitHub-hosted debug-подпись может меняться: установка поверх прежнего APK не гарантирована, при удалении приложения данные теряются.

## Следующие работы по приоритету

1. Диагностика ошибок API: отдельные `DiagnosticLogger`, локальный журнал с ротацией, управление подробностью, просмотр/экспорт в файл/очистка из настроек, **без записи API-ключей и содержимого чатов по умолчанию**, нормальное сообщение об ошибке вместо `null`.
2. UI: **Material 3 `DropdownMenu` рядом с кнопкой** информации о чате, для истории — левый `ModalNavigationDrawer`; не выводить строку контекста постоянно, только кольцо и подробности по нажатию.
3. Отдельный `ChatComposer`: ввод, `+`, микрофон и динамический Send→пульсирующий Stop **внутри одного поля**. Stop должен реально прерывать API-запрос; сохранять набранный текст, не создавать пустой ответ.
4. Офлайн-распознавание русского: отдельный модуль `SpeechInputManager`, компактная модель порядка 45–60 МБ. Пользователь предполагает **Vosk**, но название прежней модели не установлено. `vosk-model-small-ru-0.22` — кандидат для проверки качества/скорости/памяти и лицензии, не окончательный выбор. Диктовка заполняет поле для редактирования, не отправляет автоматически. Локальное STT — исключение из API-only для LLM/эмбеддингов/саммаризации.
5. Сохранить видимость status/navigation bars в теме Material 3, не допускать белых полос, учитывать клавиатуру. Далее улучшать гибридный RAG, долговременную память, тарификацию, стабильную подпись и бэкап.

## Принципы

- Все новые возможности **только отдельными Kotlin-классами/модулями**. Не растить `ChatController`/`ComposeChatActivity` в монолит.
- Сначала назвать затрагиваемые классы и план изменений; после реализации проверить `assembleDebug` и регрессии, честно указать непроверенное, обновить Roadmap.
- Roadmap живой: новые согласованные задачи добавляются по ходу разработки. Полная оригинальная история никогда не теряется при компактизации.
